# AI Skill 安全 — 四部法规相关条款索引

> **文件说明**：本索引供 OpenClaw / PermAudit 论文 Fig 4B、Methods 与合规讨论使用。  
> **重要声明**：四部法律均**未定义 “Skill / Agent 插件”**；下列映射为 **Skill 在运行中处理个人信息或作为 AI 系统组件** 时的**可能适用条款**，**不构成法律意见**。定稿前须由具备资质的法律专业人士复核。  
> **编制日期**：2026-05-22  
> **法规版本**：GDPR (EU) 2016/679；EU AI Act (EU) 2024/1689；CCPA/CPRA (Cal. Civ. Code §1798.100 等，Operative 2023+)；《个人信息保护法》（2021）；《生成式人工智能服务管理暂行办法》（2023，个保法配套）

## 一、适用场景（Skill 安全）

| 场景 | 典型原子/路径 | 法规关切 |
|------|---------------|----------|
| 读取/外发个人或连接器数据 | R8, I3, O5, W2 | 合法处理、出境/跨境、安全 |
| 凭证/身份代理 | I1–I5, U3, U4 | 访问控制、身份真实 |
| 自动监控/外发/判定 | A5, A6, Q4, G2, O5 | 自动化决策、透明度 |
| 定位/音视频 | S1–S4 | 敏感个人信息 |
| 越权与权限继承 | I5, R10, K3 | 最小必要、安全措施 |
| 投毒/破坏/篡改 | W3, X1, O4 | 完整性、网络安全（AI 法尤甚） |
| 拟真消息/误导 | G2, R2, O5 | 透明、公平、反操纵 |

## 二、GDPR（General Data Protection Regulation）

**正式名称**：Regulation (EU) 2016/679  
**官方文本**：[EUR-Lex](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32016R0679) | [gdpr-info.eu](https://gdpr-info.eu/)

| 条款 | 主题 | 核心要求（摘要） | 与 Skill 安全的关联 |
|------|------|------------------|---------------------|
| **Art. 5** | 处理原则 | 合法、公平、透明；目的限制；**数据最小化**；准确性；存储限制；**完整性与保密性**；问责 | Skill 声明权限 vs 实际实现（PDEI）；过度申请原子能力 |
| **Art. 6** | 处理的合法性 | 六项合法基础（同意、合同、法定义务等） | Skill 读取 PI 须具备合法基础 |
| **Art. 9** | 特殊类别数据 | 生物识别、位置、健康等；原则上禁止处理，例外严格 | PH 类 Skill（摄像头、定位、轨迹） |
| **Art. 12–15** | 透明与信息权 | 告知处理目的、方式、存储期限、权利行使方式等 | Skill 披露不足、暗箱处理 |
| **Art. 22** | 自动化决策 | 不得仅依自动化（含画像）作出产生法律效力或**类似重大影响**的决定；须保障说明权、人工介入等 | AU/SM 类自动外发、自动判定链路 |
| **Art. 25** | 设计与默认保护 | **Privacy by design / by default**；默认仅处理必要数据 | Skill 默认宽权限、插件生态设计 |
| **Art. 32** | 处理安全 | 依风险采取适当技术与组织措施：假名化/加密、恢复能力、测试等；防**未经授权或非法处理**及意外丢失、破坏、损坏 | **Skill 安全核心条款**：访问控制、防泄露篡改 |
| **Art. 33–34** | 泄露通知 | 72 小时内向监管机构报告；向数据主体通知（特定条件） | Skill 导致数据外泄的事件响应 |
| **Art. 35** | DPIA | 高风险处理须事先评估（含系统性监控、敏感数据、自动化决策等） | 高风险 Skill 上架/部署前 |
| **Art. 44–49** | 国际传输 | 向第三国传输的条件（ adequacy、SCC、BCR 等） | 连接器数据传至境外 API |
| **Art. 82** | 损害赔偿 | 因违反 GDPR 造成损害须赔偿 | 合规压力（非设计条款） |

**与本项目 8 类滥用模板的主要对应（GDPR）**

| 系统破坏类 | Art. 5(1)(f), 32 |
| 隐蔽操控与社会工程类 | Art. 5(1)(a), 12–15, 22 |

## 三、EU AI Act（Artificial Intelligence Act）

**正式名称**：Regulation (EU) 2024/1689  
**官方文本**：[EUR-Lex 2024/1689](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32024R1689) | [AI Act Service Desk](https://ai-act-service-desk.ec.europa.eu/)

> **适用边界**：义务强度取决于 AI 系统是否属于**禁止性 AI**、**高风险 AI**、**有限风险（透明度）**或 **GPAI（通用目的 AI）**。Agent Skill 可能被认定为 AI 系统的组件或部署形态，需逐案分类。

| 条款 | 主题 | 核心要求（摘要） | 与 Skill 安全的关联 |
|------|------|------------------|---------------------|
| **Art. 4** | AI 素养 | 提供者/部署者须采取措施确保人员具备足够 AI 素养 | 平台与开发者治理 |
| **Art. 5** | 禁止的 AI 实践 | 操纵性 AI、社会评分、实时远程生物识别（例外）等**禁止** | 极端 SM/PH 类滥用 |
| **Art. 6–7** | 高风险分类 | Annex III 等规则；实质高风险场景 | 是否触发完整合规包 |
| **Art. 9** | 风险管理系统 | 高风险 AI 须建立并维护**全生命周期风险管理** | Skill 作为高风险系统组件时的治理 |
| **Art. 10** | 数据与数据治理 | 训练/运行数据须相关、有代表性、尽可能无错误；对特殊类别数据的处理限制 | 使用用户数据训练或持续学习 |
| **Art. 11** | 技术文档 | 高风险 AI 须技术文档（Annex IV） | Skill 能力边界、权限说明 |
| **Art. 13** | 透明度 | 向部署者提供能力、限制、预期性能等**充分信息** | Skill 说明与实际权限不一致 |
| **Art. 14** | 人工监督 | 高风险 AI 须可被**有效监督**；人可理解、可干预 | 全自动外发/破坏链路 |
| **Art. 15** ⭐ | 准确、稳健与网络安全 | 适当准确性、稳健性、**网络安全**；防未授权第三方篡改用途/输出/性能；须防 **data poisoning、model poisoning、adversarial examples、confidentiality attacks** 等 | **与 Skill 投毒、篡改、越权执行高度对应** |
| **Art. 16–21** | 提供者义务 | 合规、QMS、日志、纠正措施、监管合作等 | AI 平台对 Skill 生态责任 |
| **Art. 19** | 自动日志 | 高风险 AI 须自动记录事件/logs（可追溯） | 审计权限滥用 |
| **Art. 25** | 价值链责任 | 上游组件提供者须提供必要信息；下游整合者义务 | **Skill 商店 / 第三方 Skill** |
| **Art. 26–27** | 部署者义务 / 基本权利影响评估 | 部署者按说明使用；特定公共/私营部署须 FRIA | 企业部署 Agent+Skill |
| **Art. 50** | 透明度（有限风险） | 与自然人交互须告知其为 AI；合成内容须**机器可读标识**等 | 用户不知在与 Agent 交互 |
| **Art. 52–56** | GPAI 模型义务 | 技术文档、版权政策、训练数据摘要；**系统性风险**模型额外义务 | 底座模型 + Skill 组合 |

**与本项目 8 类滥用模板的 mainly 对应（EU AI Act）**

| 滥用类 | 优先条款 |
|--------|----------|
| 数据外泄类 | Art. 10, 15(5), 19, 25 |
| 身份冒用类 | Art. 13, 14, 15(5) |
| 执行投毒类 | **Art. 15(5)**（data/model poisoning）, Art. 10 |
| 自动扩散类 | Art. 5, 13, 14, 50 |
| 物理感知与现实干扰类 | Art. 5, 9, 27 |
| 权限蠕动类 | Art. 13, 14, 25 |
| 系统破坏类 | Art. 15(4)(5)（稳健性、防篡改） |
| 隐蔽操控与社会工程类 | **Art. 5**（操纵性 AI）, Art. 50, 13 |

## 四、CCPA / CPRA（California Consumer Privacy Act as amended）

**管辖**：加州消费者隐私；**Operative** 2023 起 CPRA 修正案广泛适用。  
**官方文本**：[CPPA Statute PDF](https://cppa.ca.gov/pdf/20260101_ccpa_statute.pdf) | [Cal. Civ. Code §1798.100+](https://leginfo.legislature.ca.gov/faces/codes_displayText.xhtml?lawCode=CIV&part=4&title=1.81.5)

| 条款 / 章节 | 主题 | 核心要求（摘要） | 与 Skill 安全的关联 |
|-------------|------|------------------|---------------------|
| **§1798.100(a–d)** | 收集的一般义务 | 收集时告知类别与目的；**目的兼容**处理；不保留不必要信息 | Skill 收集/使用超出声明 |
| **§1798.100(e)** ⭐ | **合理安全措施** | 须实施与信息性质相适应的**合理安全程序与措施**，防未经授权或非法访问、破坏、使用、修改或披露（参见 **§1798.81.5**） | **Skill 安全核心（加州）** |
| **§1798.105** | 删除权 | 消费者可请求删除；服务提供者须配合 | 数据残留于 Skill 日志 |
| **§1798.106** | 更正权 | 消费者可请求更正不准确 PI | 错误画像/推断 |
| **§1798.110–115** | 知情/access | 知悉、访问、披露来源与第三方共享 | 透明度 |
| **§1798.120** | 选择退出出售/共享 | 消费者可 opt-out of **sale or sharing** | 向第三方 API 共享 Skill 处理数据 |
| **§1798.121** | 限制敏感 PI | 限制敏感个人信息使用与披露 | 定位、生物识别等 |
| **§1798.130** | 通知与请求机制 | 隐私政策、请求提交方式、响应时限 | 平台披露 Skill 数据处理 |
| **§1798.140(y)(z)** | 定义：Processing / **Profiling** | Processing 含自动化操作；**Profiling** 为自动化处理以评估工作、经济、健康、偏好、行为、**位置**等 | 自动监控、用户画像类 Skill |
| **§1798.140(l)** | 定义：Dark pattern | 损害用户自主选择的界面设计（规章进一步定义） | 隐蔽操控类 |
| **§1798.81.5** | 民事法典信息安全 | 持有 PI 的企业须实施**合理安全** | 与 §1798.100(e) 联动 |
| **§1798.150** | 数据泄露私人诉权 | 未维持合理安全导致未加密 PI 泄露等，消费者可起诉 | 泄露后果 |
| **§1798.185** | 规章授权 | CPPA 规章：含 **automated decision-making technology (ADMT)**、风险评估、审计、opt-out 信号等 | **ADMT/ profiling 合规框架** |

**CPRA 规章补充（非成文法条文，但合规常引用）**

- **Automated Decision-Making Technology (ADMT)**：对消费者作**重大决定**的 ADMT 须风险评估、披露、opt-out 等（见 CPPA ADMT 规章，2025 年前后生效阶段规则持续更新）。
- **Risk Assessments**：出售/共享 PI、处理敏感 PI、特定 ADMT 等须进行并留存**隐私风险评估**。

**与本项目 8 类滥用模板的 mainly 对应（CCPA/CPRA）**

| 滥用类 | 优先条款 |
|--------|----------|
| 数据外泄类 | §1798.100(e), 1798.81.5, 1798.120, 1798.150 |
| 身份冒用类 | §1798.100(e), 1798.81.5 |
| 执行投毒类 | §1798.100(e)（完整性）；直接条款较弱 |
| 自动扩散类 | §1798.140(z), 1798.185（ADMT） |
| 物理感知与现实干扰类 | §1798.121, 1798.140(ae) 敏感 PI |
| 权限蠕动类 | §1798.100(c) 目的限制, 1798.100(e) |
| 系统破坏类 | §1798.100(e), 1798.150 |
| 隐蔽操控与社会工程类 | §1798.140(l) dark pattern, ADMT 规章 |

## 五、《中华人民共和国个人信息保护法》（PIPL）

**通过**：2021年8月20日；**施行**：2021年11月1日  
**官方文本**：[国家网信办](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

| 条款 | 主题 | 核心要求（摘要） | 与 Skill 安全的关联 |
|------|------|------------------|---------------------|
| **第5–8条** | 处理原则 | 合法正当必要诚信、**最小必要**、公开透明、保证质量 | 权限冗余、隐瞒处理 |
| **第9条** ⭐ | 安全责任 | 处理者须对处理活动负责，**采取必要措施保障个人信息安全** | Skill/平台安全义务总纲 |
| **第10条** | 禁止非法处理 | 不得非法收集、使用、加工、**传输**、买卖、提供、公开 PI | 数据外泄、越权传输 |
| **第13–14条** | 合法性基础与同意 | 七种情形；同意须自愿明确；敏感信息**单独同意** | 默认授权、捆绑同意 |
| **第16–17条** | 告知 | 显著、清晰、完整告知目的、方式、种类、保存期限等 | Skill 说明与实际不符 |
| **第24条** | **自动化决策** | 透明、公平；推送/营销须提供非个性化选项或便捷拒绝；重大影响时说明权与拒绝权 | AU/SM 类 Skill |
| **第28–30条** | **敏感个人信息** | 定义（含生物识别、**行踪轨迹**、金融账户、未成年人等）；单独同意；特定目的与严格保护 | PH/DL 类 Skill |
| **第38–40条** | **出境** | 安全评估、认证、标准合同等条件 | 数据传至境外服务 |
| **第44–47、50条** | 个人权利 | 知情、决定、查阅复制、更正删除、限制拒绝；便捷受理机制 | 用户权利保障 |
| **第51条** ⭐ | **安全措施** | 防未经授权访问及泄露、篡改、丢失；内控、分类、**加密/去标识化**、**操作权限**、培训、应急预案等 | **Skill 最小权限、访问控制** |
| **第52–54条** | 保护负责人、审计 | 达到一定规模指定负责人；**定期合规审计** | 大型 Skill 平台 |
| **第55–56条** | **PIPIA** | 敏感 PI、自动化决策、委托/提供/公开、出境等须事前**影响评估** | 高风险 Skill |
| **第57条** | 安全事件 | 泄露、篡改、丢失须**立即补救并通知** | 外泄事件 |
| **第58条** | **重要互联网平台** | 平台规则、停止服务严重违规者、社会监督等 | Skill **应用商店/分发平台** |
| **第59条** | 受托处理 | 受托方须保障安全并协助处理者 | 第三方 Skill 代处理 |
| **第73条（附则）** | 定义 | **自动化决策**定义 | 法律适用边界 |

## 七、使用建议（论文 / Fig 4B）

1. **正文或 Supplementary Table** 可逐条引用上表，**勿**将本文件中的“优先对应”直接量化为 0–1 冲突分。  
2. Fig 4B 热图若用 **专家规则打分**，建议每格附 **1–3 条条款 + 要件说明 + 复核人**。  
3. Skill 仅处理**非个人信息**的纯系统破坏场景，个保法/CCPA/GDPR 适用性下降，宜并列引用 **EU AI Act Art. 15**、**网络安全法**、**数据安全法**。  
4. 法规更新频繁（尤其 CCPA 规章、EU AI Act 实施细则），投稿前核对条款是否修订。
